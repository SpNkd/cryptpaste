# Security policy

## Отчёты об уязвимостях

Не публикуйте рабочие exploit details в открытом issue. Для координации
напишите владельцу репозитория через профиль GitVerse/GitHub с описанием
затронутой версии, воспроизводимости и возможного воздействия.

## Security invariants

- plaintext/password/key не должны попадать в backend request;
- не использовать `Math.random()` для криптографических значений;
- не добавлять trackers или внешние JS CDN;
- не логировать body запросов;
- не добавлять секреты в Git, URL или frontend build;
- изменения crypto envelope должны сопровождаться обновлением versioning и
  тестов.

## Ответственное раскрытие

После подтверждения проблемы сначала согласуйте безопасное раскрытие,
обновление и release notes. MIT-лицензия не является обещанием managed SLA.
